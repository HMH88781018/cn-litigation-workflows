## 1. 唯一真源

建立字段—位置映射：

| ID | 锁定值 | 来源 | 证据清单 | 证据目录/材料 | 计算表 | 起诉状/其他文书 | 同步规则 |
|---|---|---|---|---|---|---|---|
| PTY-* | 主体 | 身份/登记 | 提交方、证明目的 | 归属 | 权利人/义务人 | 主体栏、诉请 | 逐字一致 |
| E-* | 证据名称/页码 | 最终材料册 | 名称、目的、页码 | 顺序、起止页 | 证据映射 | 正文引用 | 成册后同源回填 |
| DMG-* | 分项金额 | 计算明细 | 损失证明 | 票据页码 | 公式、金额 | 诉请 | 计算表为金额真源 |
| POL-* | 限额/条款 | 保单/官方来源 | 保险证明 | 保单页码 | 分层参数 | 责任主体 | 事故日版本一致 |
| PAY-* | 已付款 | 付款凭证 | 抵扣事实 | 凭证页码 | 付款台账 | 诉请余额 | 按付款人抵扣 |

任何字段变化先检索全部位置，再按当前授权范围同步。禁止在多份文件中分别手改同一关键金额或页码。

## 2. 证据闭合

### 2.1 正向

```text
诉请/抗辩
→ 法律要件
→ 待证事实
→ 证据 ID
→ 证据材料页码
→ 证明目的
```

### 2.2 反向

```text
证据材料
→ 准确名称和来源
→ 证明对象
→ 争点/损失项目
→ 诉请或抗辩
```

检查：

- 每项核心诉请或抗辩有证据承接或明确缺口；
- 每项证据有具体证明对象，不夹带无关材料；
- 证据名称、顺序号、册次、起止页在清单、目录、材料和正文引用中一致；
- 身份/程序材料与实体证据按证明性质区分；
- 证据内容没有被摘要、OCR或证明目的夸大；
- 成册后没有再插页、删页或替换而未重编。

## 3. 金额闭合

每项金额记录：

`权利人｜项目｜基数｜数量/期间｜标准｜系数｜扣减｜舍入｜金额｜证据 ID｜是否主张｜是否计入总额`

闭合：

```text
Σ同一权利人计入总额的分项 = 个人小计
Σ个人小计 = 案件损失总额
案件损失总额 = 计算表总额
计算表总额 = 起诉状诉请总额
需要引用时 = 标的额/保全金额/其他程序文书金额
差额 = 0.00元
```

另行核对：

```text
认可损失
= 交强险 + 商业险 + 侵权人理论责任 + 受害人自担/依法不归责部分

每名付款义务人理论责任
= 已认可付款 + 尚欠金额

票据/期间明细合计
= 对应赔偿项目汇总
```

内部计算可保留精度；正式金额按统一规则舍入。不得手调某个分项消灭0.01元差额。

再审案件改用：

```text
原审请求
→ 原判支持/驳回
→ 已履行
→ 再审审查范围
→ 拟撤销或变更部分
→ 再审请求
→ 金额及程序差额
```

一般一审公式“计算表总额＝起诉状诉请总额”在再审模式标为 `NA`，不得硬套。

## 4. 多主体隔离

每名伤者、死者、权利人、被扶养人、车辆和保单使用独立 ID。

检查：

- 病历、票据、工资、误工期间、护理、伤残、扶养和付款归属于正确主体；
- 共同证据明确覆盖主体和证明范围；
- 每人先独立小计，再案件汇总；
- 多车保单限额没有重复使用；
- 同一付款没有在不同伤者或义务人处重复抵扣；
- 分诉/合并、共同侵权或连带责任未确定时标记 `BLOCK`，不先混表。

## 5. 文件与视觉复核

### 5.1 DOCX/PDF

1. 保存、关闭并重新打开 DOCX；
2. 转为 PDF；
3. 将 PDF 全部页面栅格化；
4. 100%逐页检查，关键表格、页码和签章区放大检查；
5. 核对 DOCX/PDF 的文字、表格、页序和页码；
6. 检查移动端预览和黑白打印可读性。

不得存在：

- 裁切、重叠、压线、乱码、异常竖排；
- 表格越版心、列宽漂移、边框断裂；
- 长表续页无表头；
- 页码遮挡票据、印章、二维码或正文；
- 意外空白页、落款拆页、签署空间不足；
- 母版以外的未授权结构变化。

### 5.2 XLSX

1. 检查关键输入、参数、公式和结果区；
2. 扫描 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`；
3. 追踪总额、保险分层、被扶养人和付款余额的公式来源；
4. 渲染每张工作表或其核心打印区域；
5. 核对标题、列宽、换行、数字格式、冻结窗格和打印区域；
6. 运行年龄、限额、空值、负数、零分母、多主体和重复付款测试。

输入、来源参数、人工判断、公式和结果必须同时以文字角色和颜色区分；不能只靠颜色。

## 6. 定点修改

`POINT_EDIT` 建立白名单：

| 修改 ID | 文件/位置 | 修改前 | 修改后 | 来源 | 允许关联修改 | 禁止范围 |
|---|---|---|---|---|---|---|

冻结基线文件哈希、页数、表格结构和页面图。完成后比较文字、结构、公式、对象和页面图。

通过条件：

```text
实际差异集合 = 批准差异集合
未授权差异集合 = 空集
```

范围外问题只报告。若指定修改必然引起页码、总额或关联字段失配，先请求扩展白名单；不得暗中全改。

## 7. 缺陷分级

| 级别 | 例子 | 放行 |
|---|---|---|
| P0 | 错案、错法院、错主体、错证件号、错证据册、错总额、公式失真、文件损坏 | 必须清零 |
| P1 | 错日期、页码、证据编号、原件状态、责任比例、统计年度、保险限额、跨文书不一致 | 必须清零 |
| P2 | 不影响提交的轻微样式或内部记录问题 | 记录并决定 |

已知 P0/P1 未清零时保持 `DRAFT`，不能因期限紧而标记 `RELEASE`。

## 8. RELEASE 标准

先按主模式建立“适用门槛表”。与本次交付无关的指标写 `NA｜具体原因`：例如纯证据任务的赔偿/保险/付款差额，或已明确为纯数值测试的证据册页码。`NA` 不是跳过本来应当完成的工作；只在主模式和用户授权范围确实不包含该交付时使用。

第二复核人应当未承担本版主要制作，并具有与复核范围相匹配的法律、证据整理
或赔偿计算能力。复核记录至少写明复核人/角色、日期、范围、直接查看的原始
材料与基线、发现、处理结果和签署状态。模型反馈只能作为辅助线索，不构成
独立人工复核或法律批准。

| 指标 | 标准 |
|---|---:|
| 法院/程序/案由/模板确认 | 100% |
| 关键字段来源可追溯 | 100% |
| 证据页码与冻结材料册一致 | 100% |
| 诉请—事实—证据覆盖 | 100%或缺口明示且不冒充正式版 |
| 分项—总额—诉请差额 | 0.00元 |
| 保险分层差额 | 0.00元 |
| 付款余额差额 | 0.00元 |
| 跨主体污染 | 0 |
| 重复票据/重复付款 | 0 |
| 未授权差异 | 0 |
| 公式错误 | 0 |
| DOCX/PDF/XLSX 打开与渲染 | 通过 |
| 全部页面/工作表视觉检查 | 100% |
| P0/P1 | 0 |

最终回复先说明 `RELEASE`、`DRAFT` 或 `REVIEW`，再列成果、版本、未改动范围、签名/日期待办、剩余风险和唯一有效文件。未放行时只列最小阻断信息，不用“最终版”“正式版”命名。
