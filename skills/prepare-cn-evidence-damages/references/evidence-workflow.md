## 1. 概念边界与规则优先级

全国性规范没有把普通民事、行政诉讼中的“证据清单”和“证据材料目录”定义为名称固定、彼此排他的两种法定文书。法院文书样式和地方指引还会交替使用“证据清单”“证据目录”“证据目录清单”等名称。不得把内部命名习惯表述成全国统一强制规则。

按以下顺序确定名称、栏目和版式：

1. 本案法院、仲裁机构的现行母版、举证通知和立案平台字段；
2. 用户对本案的明确指令；
3. 全国性法律、司法解释关于提交内容的最低要求；
4. 本参考的功能性双件制。

无固定母版时采用：

| 文件 | 核心功能 | 位置 |
|---|---|---|
| 证据清单 | 说明“用什么证据证明什么事实”，便于提交、接收和审理 | 独立成文、单独提交 |
| 证据材料目录 | 说明“材料在证据册哪里”，便于定位实体材料 | 并入证据材料册，通常位于封面之后 |

当事人制作的证据材料目录不等于法院归档使用的卷内目录。刑事公诉中的法定“证据目录”也不适用本工作流。

法院母版存在时，保留其标题、列序、列宽、合并关系、签章区、页眉页脚和分页结构。内部模型中多出的信息放入母版已有备注栏或另附受控说明；不得擅自增删栏目或“纠正”法院名称。

## 2. 统一数据底稿

先建立一个唯一证据 manifest，再从同一底稿生成清单和目录：

| 字段 | 含义 |
|---|---|
| submission_batch | 首次提交、补充证据第一次等 |
| party_role | 原告、被告、第三人或申请人 |
| evidence_no / sub_no | 证据顺序号与子项号 |
| document_name | 材料首页或原件中的准确名称 |
| issuer_and_date | 形成主体、日期、文号 |
| source | 材料形成或取得来源 |
| holder | 原件或原始载体持有人 |
| evidence_type | 书证、物证、电子数据、视听资料等 |
| material_item_count | 不同材料的件数 |
| submission_set_count | 实际向法院提交的套数 |
| pages_per_set | 每套实际页数 |
| proof_object | 具体待证事实 |
| proof_purpose | 对诉请、抗辩或损失项目的作用 |
| booklet_no | 第几册或哪一次补充证据册 |
| page_start / page_end | 最终成册后的连续页码 |
| original_status | 原件、复制件、核验和保管状态 |
| source_file | 对应源文件 |
| file_hash | 必要时记录电子文件校验值 |
| notes | 隐私、译文、电子载体、异常和补充批次 |

严格分开：

- 证据顺序号：逻辑索引，如“证据3”“证据3-2”；
- 材料连续页码：物理位置，如“证据册第12—18页”；
- 材料件数：有几件不同材料；
- 提交套数：向法院交几套副本；
- 每套页数：一套有多少页。

母版只有“份数”且含义不明时，先查填写说明；仍无法确认，在备注中写清“材料1件，提交×套，每套4页”，不得用一个数字混写三个概念。

## 3. 制作前控制

### 3.1 模板闸门

锁定：法院、案由、程序阶段、案号、提交方、提交批次、举证期限、对方当事人人数、提交介质和法院母版。

案号尚未取得时留空。未经明确授权，提交人签名、盖章和日期全部留出实际签署空间。

### 3.2 完整读取与证据边界

逐份检查：

- 首页、续页、附件、背面、印章、签字、日期和文号是否完整；
- 扫描是否缺页、重页、倒置、裁切、遮挡或模糊；
- 同一文件的正文与附件是否应作为一个证据项；
- 不同材料是否被错误合并为“相关资料一组”；
- 原件、加盖专用章复制件、普通复制件和电子原始载体的状态；
- 是否需要译文、音视频文字整理稿、电子数据提取说明；
- 是否含隐私、商业秘密或其他需申请保护的信息。

OCR 只作检索层，不替代原始图像，不据 OCR 猜测证件号、金额、日期、印章或手写内容。

### 3.3 待证事实矩阵

先建立：

`诉请/抗辩 → 法律要件事实 → 举证责任 → 证据 ID → 缺口`

不得先堆材料，再倒填“证明案件事实”“证明原告主张成立”等空泛目的。

### 3.4 定序

按诉请或抗辩的要件事实分组，组内通常按时间排序：

1. 主体与基础法律关系；
2. 权利义务产生；
3. 履行、侵权或行政行为事实；
4. 过错、责任与因果关系；
5. 损害及金额；
6. 催告、时效和程序事实；
7. 其他辅助证据。

证据编号冻结后不得静默重排。补充证据优先单独成册并标明批次；法院要求重编时制作新旧编号对照表。

## 4. 证据清单

### 4.1 默认列序

先服从本案锁定样本。没有固定样本时采用：

`序号｜争点/诉请｜证明目的｜证据名称｜页码范围｜形成主体/日期（必要时）｜原件状态/备注`

如需满足接收核对，可增加来源、证据形式、材料件数、提交套数和每套页数。不得声称该列序为全国统一格式。

### 4.2 证明对象和目的

证明对象写成事实命题：

`主体 + 时间/期间 + 行为或状态 + 对象 + 结果`

合格：

> 证明被告于×年×月×日签收涉案货物20箱，签收单未记载数量及外观异议；该事实对应原告第1项给付请求。

不合格：

- 证明被告违约，应承担全部责任；
- 证明本案全部事实；
- 证明原告主张合法合理；
- 证明被告应败诉。

责任认定书的证明目的应写其记载的事故时间、地点、参与主体、车辆和交管部门对事故成因、交通违法过错的认定；同时注明民事责任比例由法院依法判断，不能把交警责任认定机械等同于最终民事赔偿比例。

一项证据承载多个证明事项时分项表述。多份证据共同证明同一事实时可以组证，但必须列明每一子材料，且组内材料确有共同证明目的。

### 4.3 页码

初稿 manifest 可以暂空，但正式清单不得估算页码。必须待证据册最终合并、连续编页、冻结后回填。

证据清单独立提交时，默认不计入证据材料正文连续页码；本案法院另有规则时从其规则。

### 4.4 输出

独立输出 DOCX/PDF。长表自然跨页并重复表头。签名、盖章不得代作；提交人打印名称和日期默认留空。只有用户明确授权且日期已核实为实际签署/提交日期时才可预填日期，并提示提交前再次核对；不得虚填提交日期。

## 5. 证据材料目录与成册

### 5.1 默认目录字段

`材料序号｜对应证据编号｜材料准确名称｜起页｜止页/页码范围｜页数｜载体/备注`

固定样本含“证明目的”时保留；无样本时目录以物理导航为主，证明逻辑放在独立证据清单。

### 5.2 唯一生产顺序

```text
完整读取
→ 去重、辨真并划定证据边界
→ 冻结证据顺序号
→ 调整方向、尺寸和清晰度
→ 按冻结顺序合并证据材料
→ 按本案页码政策连续编页
→ 逐项核对起止页
→ 回填证据材料目录
→ 从同一 manifest 回填独立证据清单
→ 核对诉状、计算表、代理词和质证意见中的引用
→ 冻结最终文件并记录版本
```

不得先猜页码再合并，也不得回填后插页却不更新所有下游引用。

### 5.3 页码政策

开工时记录：

| 项目 | 本案规则 |
|---|---|
| 封面是否计页 |  |
| 目录是否计页 |  |
| 分隔页/说明页是否计页 |  |
| 页码起始值 |  |
| 页码位置和样式 |  |
| PDF 页面序号与印刷页码偏移 |  |
| 多册是否连续编号 |  |
| 补充证据是否独立编号 |  |

无固定规则时，可采用“封面、目录不计入证据正文页码，仅证据材料正文从1连续编号”的内部默认，但必须明确标记为本案选择，不能冒充法定要求。

规则：

- 以最终 PDF 实际页面为准，不按扫描张数或原始文件名估算；
- 正反面均有内容的，每一面计一页；
- 分隔页、说明页、译文、文字整理稿一旦承载内容并纳入正文，就按本案页码政策计页；
- 同一证据尽量连续放置；页码不连续时拆分目录项；
- 页码不得压住正文、签章、票据金额、二维码或影像边缘；
- 任何增、删、替换、旋转导致页面变化后，重新编页、回填和复核；
- 已送达版本不得静默替换。

正文引用写成：

> 见证据1，即第一册证据材料第1—4页。

不得只写“见第1页”或“见证据第1页”，以免混淆顺序号与材料页码。

## 6. 字段写法

| 字段 | 合格写法 | 禁止写法 |
|---|---|---|
| 证据名称 | 原样写文件标题，并补出具单位、日期、文号 | 相关资料、医疗材料若干 |
| 来源 | 由××医院出具；从××平台账户导出 | 来源合法、原告提交 |
| 持有人 | 原件由原告持有；原始载体由××保管 | 与来源混写 |
| 形式 | 书证；电子数据（微信导出件及打印件） | 只写复印件 |
| 数量 | 材料1件，提交×套，每套4页 | 含义不明的“3份” |
| 证明对象 | 具体的主体、时间、行为、对象和结果 | 胜诉结论、法律口号 |
| 页码 | 第一册第1—4页，成册后回填 | 估算页码、把证据3写成第3页 |
| 原件状态 | 复制件；原件由原告持有，庭审携带核验 | 未核对却写与原件一致 |
| 备注 | 隐私、译文、文件名、时长、补充批次 | 长篇法律论证 |

电子证据示例：

> 电子数据（微信聊天记录导出件及打印件）；来源于原告与被告的微信账号；原始载体由原告持有；随附账号主体说明、提取过程说明及文件校验值。

不得选择性截取到改变原意。音视频注明文件名、时长、载体和关键时点，文字整理稿必须能够回指原音视频。

## 7. 道路交通事故证据分组

按案件事实取舍，不机械要求每组都存在：

| 分组 | 常见材料 | 对应事项 |
|---|---|---|
| 事故与责任 | 事故认定书、现场图、照片、询问材料 | 时间、地点、车辆、行为、事故成因 |
| 车辆与保险 | 行驶证、驾驶证、交强险及商业险保单、条款 | 责任主体、保险期间和限额 |
| 治疗与费用 | 病历、诊断、医嘱、票据、费用明细 | 伤情、因果关系、医疗和后续治疗 |
| 误工 | 劳动合同、工资流水、个税、单位证明、休假证明 | 收入状况、实际减少、误工期间 |
| 护理与营养 | 护理医嘱、鉴定意见、护理人员收入材料 | 人数、期限、标准、依赖程度 |
| 伤残 | 鉴定意见、定残日、辅助器具意见 | 等级、系数、护理依赖和器具 |
| 死亡与扶养 | 死亡证明、亲属关系、年龄、劳动能力和收入来源材料 | 死亡赔偿、丧葬和被扶养人生活费 |
| 财产与经营 | 定损、维修、发票、营运许可、停运资料 | 修复、重置、施救、停运和替代交通 |
| 已付款与基金 | 垫付款、理赔记录、医保/工伤基金及救助基金支付记录 | 防止重复计算并确定各付款人余额 |
| 程序与法源版本 | 原审诉请、裁判、送达/生效材料、再审申请、再审裁定或决定 | 判断是否终审、再审审查范围和新旧法衔接 |

工资流水只能证明实际入账事实，不能在缺乏其他材料时自动等同于稳定工资标准或全部误工损失。

## 8. 补充证据

默认建立：

- 《补充证据清单（第一次）》；
- 《补充证据册（第一次）》，内部含补充证据材料目录；
- 继续原编号或按法院指令编号；
- 补充册可独立从1编页，但引用必须写明册次；
- 法院要求合并重编时，生成新旧证据编号和页码对照表。

不得把新证据直接插入已送达旧册，导致旧页码和庭审引用失效。

## 9. 质量控制

### 9.1 内容

- [ ] 每项名称与材料首页一致，附件和背面完整；
- [ ] 来源、持有人、原件状态均有材料依据；
- [ ] 每项证据至少对应一个具体待证事实；
- [ ] 证明范围没有超出证据实际内容；
- [ ] 身份、授权、律师执业材料未冒充实体证据；
- [ ] 交通事故票据与赔偿计算表逐笔勾稽。

### 9.2 编号和页码

- [ ] 顺序号与连续页码分开管理；
- [ ] 编号唯一，无重号和无故跳号；
- [ ] 页码来自最终成册文件，不是预估；
- [ ] 每项起止页已实际打开核对；
- [ ] 目录、清单、材料和正文引用一致；
- [ ] PDF 页面序号与印刷页码偏移已记录。

### 9.3 文件和签署

- [ ] 清单独立；目录已并入证据册；
- [ ] 长表重复表头，文字无裁切或异常跨页；
- [ ] PDF 无缺页、重页、倒置、模糊和页码遮挡；
- [ ] 未代签或代盖；提交人打印名称、日期按默认留空，或已有明确授权及真实日期依据；
- [ ] 页码无法核实时标记 `DRAFT`，不冒充正式版；
- [ ] 最终文件已逐页视觉检查。
