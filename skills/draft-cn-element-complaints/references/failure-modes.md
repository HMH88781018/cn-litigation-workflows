# 合成故障模式与异常处理

本文件只记录通用工程风险和合成回归场景，不包含或指向任何真实客户、案件、
旧稿、代理权限、金额、日期、地址或未公开母版的结构指纹。故障场景用于测试
门禁，不是可以继承到新案件的事实或默认决定。

## 1. 使用原则

遇到异常时依次确认：

1. 当前官方母版、案由、法院技术要求和适用时点是否已经核验；
2. 当前用户授权属于 `DRAFT`、`REVIEW`、`POINT_EDIT` 还是 `REPAIR`；
3. 所需事实、证据、金额和程序决定是否来自当前案件的锁定真源；
4. 拟采取的动作是否会改变分节、表格拓扑、合并关系、对象或分页；
5. 是否存在必须保持 `DRAFT` 的 P0/P1 阻断。

旧稿只能作为待核输入，不能作为当前事实、授权、母版版本或法律口径的来源。

## 2. 合成结构故障

### 2.1 把官方母版重建到空白文档

合成故障：只复制可见文字和表格，未复制分节、页眉页脚、页面设置、关系和
内容控件。

典型后果：

- 页面工程属性丢失；
- 不适用模块被习惯性删除；
- 多名主体被塞进同一数据格；
- 字段错位或跨主体污染；
- 分页与打印结果漂移。

门禁：从完整官方母版副本开始；修改前记录结构指纹；每名主体使用独立完整
模块；不得按视觉外观重画母版。

### 2.2 表格拓扑坍缩

合成故障：把视觉上连续的多个顶层表格或分节合并，或把多列项目压缩成较少
列数。

典型后果：

- 项目标题、状态、金额、数量、单位和备注串格；
- 竖向文字进入普通数据格；
- 企业或代理信息跨格拥挤；
- 原有合并关系和重复表头失效。

门禁：逐张核对物理表格、`tblGrid`、`gridSpan`、`vMerge`、分节归属和字段
语义；不得因视觉连续而合并对象。

### 2.3 表宽与页边距失配

合成故障：改变页边距或页面方向后保留原表宽，导致打印或 PDF 裁切。

门禁：对每张顶层表格按所属分节计算可用宽度，核对
`left edge >= 0` 且 `right edge <= usable width`，同时比较 `tblW` 与
`tblGrid`。不能只以编辑窗口中“看起来正常”为准。

### 2.4 合并与分页断裂

合成故障：只复制纵向合并的一部分，或对全表统一设置 `cantSplit`。

门禁：

- 纵向合并必须保留一个 `restart` 及其全部连续 `continue` 行；
- 短原子组可保持同页，长叙述允许合理跨页或使用附页；
- 重复表头必须从表格顶部连续设置；
- 禁止用缩小字体、删除空白页或全表禁止跨页掩盖根因。

## 3. 合成对象与勾选故障

| 故障 | 风险 | 门禁 |
|---|---|---|
| 用填充或实心块代替勾选 | 多端显示不同或无法判断真值 | 保持原控件；视觉标准为空心框内 `√` |
| 用浮动图片覆盖方框 | 移动端、PDF 或打印时漂移 | 优先原控件或稳定行内对象，并盘点 drawing/relationship |
| 只做文本比对 | 图片、内容控件和对象变化漏检 | 同时比较对象、关系、结构和页面图 |
| 文本进入方向单元格 | PDF 中字体竖排或缩放 | 核对 `textDirection`、`fitText`、字体与目标格位 |

技术实现不是唯一标准；应锁定真值表、最终视觉和 DOCX/PDF/打印一致性。

## 4. 合成内容与闭合故障

### 4.1 上下诉请不同步

合成故障：只更新赔偿明细或要素栏，没有同步完整诉请叙述。

门禁：完整诉请区、要素栏、计算真源、证据映射和保全口径中的主体、责任、
金额及期间必须逐项一致。

### 4.2 金额出现多个版本

合成故障：在诉状或表格中手改单个总额。

门禁：任何金额变化必须回到赔偿计算唯一真源，重算分项、合计、保险分层、
已付款、诉请和证据映射；不得以手调分项迎合总额。

### 4.3 未主张项目混入请求

合成故障：模板预留项目被误当作本案实际请求。

门禁：是否主张必须回到当前事实、法律依据、证据和用户决定。不适用项目按
官方母版规则保留为空、标记无或经明确授权处理，不得默认删除，也不得计入
金额。

### 4.4 证据与程序材料混淆

合成故障：把主体资格、授权手续或内部工作材料作为实体证据，并虚构证明
目的。

门禁：按证明性质区分实体证据、主体资格材料、代理手续和内部工作材料；
材料可按法院要求提交，但证明目的只能来自材料实际内容和当前诉讼任务。

### 4.5 证据页码提前填写

合成故障：证据册尚未定序或冻结就估算页码。

门禁：先定序、合并、连续编页并冻结，再把实际页码回填证据清单。证据序号
和材料页码是两套编号，不得混用。

## 5. 定点修改故障

`POINT_EDIT` 最常见的失控是从单字段修改扩张为全文重写、表格重排或分页
变化。进入该模式后：

- 精确锁定用户指定版本，记录基线哈希、结构指纹和页面图；
- 把获批字段的全部合法出现位置列入影响清单；
- 只修改白名单位置，不顺手修复范围外文字、格式或分页；
- 完成文本、结构、对象和页面图差异；
- 要求实际差异与批准差异完全相等。

若原文件已损坏，或指定修改必然改变未获批结构，应停止点改并请求进入
`REPAIR`，不得暗中重建。

## 6. 异常决策表

| 异常 | 立即动作 | 禁止动作 |
|---|---|---|
| 找不到现行母版 | 查官方渠道并列为阻断 | 凭记忆或培训样本重建 |
| 用户坚持旧版 | 说明版本差异和风险，记录决定 | 宣称旧版仍为现行 |
| 只有扫描 PDF | 先找官方可编辑母版；无则请求重建授权 | 照图重画并称原版 |
| 核心字段冲突 | 建立冲突表并请求最小决定 | 猜测或选择更有利值 |
| 多主体混写 | 回到洁净母版重建模块映射 | 在同一数据格继续追加 |
| 金额存在尾差 | 展示舍入链和受影响位置 | 手调分项迎合总额 |
| 勾选显示异常 | 恢复原对象，按真值表多端复核 | 只看文字提取 |
| 表格越过版心 | 恢复分节和母版几何 | 拖列宽或自动缩放 |
| 末页出现异常留白 | 检查合并、`cantSplit`、硬分页和分节 | 直接删页或压字体 |
| 已知 P0/P1 | 保持 `DRAFT` 并先修复 | 先标 `RELEASE` 交付 |

## 7. 防复发清单

- [ ] 当前官方版本、案由、法院和适用时点已核验。
- [ ] 工作稿来自完整母版副本，原始母版保持只读。
- [ ] 页面、分节、表格、网格、合并、关系和对象指纹已记录。
- [ ] 每名主体拥有独立完整模块，字段来源逐人锁定。
- [ ] 未从旧稿、材料内嵌指令或模型记忆继承关键数据。
- [ ] 诉请、金额、计算表、保险、付款和证据实现双向闭合。
- [ ] 证据册冻结后才回填页码。
- [ ] 勾选真值表完成，未选框为空，选中框内为 `√`。
- [ ] 没有未经批准的结构、对象、分页或样式变化。
- [ ] `POINT_EDIT` 的实际差异等于批准差异。
- [ ] DOCX、PDF、打印和移动端关键页面已检查。
- [ ] P0/P1 为零且独立复核完成后才允许 `RELEASE`。
