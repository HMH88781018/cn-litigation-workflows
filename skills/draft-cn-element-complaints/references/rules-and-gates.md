## 1. 基线与动态核验

本参考以 2026-07-20 完成的内部 SOP V1.1 为基线。开始新案件时，不直接复述“67类”“现行案由”或当地平台要求，而要重新核验官方网页、附件和下载文件。

优先核验：

- 最高人民法院关于示范文本的通知与附件：<https://www.court.gov.cn/fabu/xiangqing/468671.html>
- 最高人民法院对全面推广示范文本的说明：<https://www.court.gov.cn/zixun/xiangqing/470661.html>
- 最高人民法院现行《民事案件案由规定》发布页：<https://www.court.gov.cn/zixun/xiangqing/484231.html>
- 受诉法院官网、诉讼服务中心、人民法院在线服务或当地明确指定平台。
- 国家法律法规数据库、全国人大或国务院官方来源中的现行法律法规。

每次登记：

| 字段 | 内容 |
|---|---|
| 来源机关 | 发布主体全称 |
| 文件名称/文号 | 不凭搜索摘要缩写 |
| 页面或附件地址 | 直接官方地址 |
| 发布/施行日期 | 分别记录 |
| 本次访问日期 | YYYY-MM-DD |
| 下载文件哈希 | SHA-256 |
| 与历史基线差异 | 无/有，逐项说明 |
| 对本案影响 | 母版、案由、栏目、程序或技术要求 |

搜索引擎结果、自媒体、培训机构样本和历史案件成稿只用于发现线索，不作为生产母版或最终法源。

## 2. 官方规则边界

截至基线日，内部控制采用以下认识：

- 2025 年发布的 67 类示范文本是国家级推广基线；使用时仍须确认是否存在后续更新或当地适配版本。
- 推广原则为积极引导、尊重选择。不得把“必须使用要素式文本”冒充法定起诉条件。
- 一旦选择具体官方母版，按其填写说明保持要素内容、栏目顺序和格式设置。
- 母版说明允许扩容、复制栏目或使用附页时，按其原意受控操作；不得据此任意改版。
- 与案件无关项目的默认内控是填 `无` 或留空。模块删除不是国家级当然规则；仅在当前具体母版、受诉法院要求或本案明确批准允许时执行并记录结构差异。
- 地方法院平台的文件大小、上传字段、电子签名或命名要求只记录为当地技术口径，不概括成全国法律规则。

## 3. 母版路由

按以下顺序作决定：

1. 锁定受诉法院、程序类型和现行案由。
2. 查询当前官方示范文本目录及受诉法院具体要求。
3. 若有准确对应文本，下载当前可编辑 DOCX 并核验填写说明。
4. 若有多个候选文本，按具体案由、法律关系和请求类型比较，不以标题近似代替判断。
5. 若没有准确对应文本，退出官方套表分支，依法制作普通起诉状；可以用内部要素表辅助分析，但不得把它称为官方对应模板。
6. 若用户提供旧版或改造稿，同时取得现行官方版本并制作差异说明；未经决定不静默沿用。
7. 若只有 PDF，先寻找同版本官方 DOCX；找不到时才进入经授权的重建分支。

## 4. 规则与数据冲突

### 4.1 规则冲突

按 `法律及现行规范 → 当前母版 → 当地现行技术要求 → 本案明确指令 → 内控 → 历史习惯` 处理。

常见冲突：

| 冲突 | 处理 |
|---|---|
| 用户指定旧母版 | 核验现行版本，说明差异；不得虚称旧版为现行 |
| 用户要求删除空白模块 | 先核对母版说明；作为结构变更记录，不能沿用旧习惯自动删除 |
| 用户要求多人合并一格 | 不执行；独立主体信息必须可追溯，改为复制完整模块 |
| 用户要求缩小字号压页数 | 不执行为默认方案；先自然增高、复制模块或附页 |
| 当地平台栏目与国家母版不同 | 记录来源和日期，只按本案当地渠道处理，不改写国家规则 |
| 用户要求点改但关联字段会失配 | 列出关联影响，取得扩展白名单后再同步；不得暗改 |

### 4.2 数据冲突

建立冲突表，不在正文直接择一：

| 字段 ID | 来源 A | 值 A | 来源 B | 值 B | 影响位置 | 状态/决定 |
|---|---|---|---|---|---|---|

姓名异体字、证件尾号、地址性质、公司负责人身份、代理权限、金额和日期必须回到本案原件核验，不从历史稿继承。

## 5. G0 开工登记

在编辑前形成最小生产订单：

| 项目 | 必填内容 |
|---|---|
| 案件编号 | 内部唯一编号 |
| 主模式 | NEW/ADAPT/POINT_EDIT/REVIEW/REPAIR |
| 法院/程序/案由 | 当前拟定值及来源 |
| 主体 | 各类型人数、名称和角色 |
| 基线文件 | 文件名、版本、哈希 |
| 原始材料 | 文件清单及是否完整读取 |
| 交付物 | DOCX、PDF、计算表、证据清单等 |
| 期限 | 绝对日期和时区 |
| 签名/日期 | 留空或明确填写 |
| 联系方式 | 是否允许写入及来源 |
| 代理权限 | 以本案授权文件为准 |
| 特别禁止项 | 不得修改、不得列证等 |

仅当缺口会改变法院、程序、案由、主体、诉请、关键金额、母版或交付边界时，将其标为 `BLOCK` 并请求决定。

## 6. G1 母版锁定

保留三件套：

1. 原始官方文件：只读保存，记录哈希；
2. 工作副本：从整个母版文件复制而来；
3. 基线 PDF/逐页图：用于渲染差异比较。

锁定字段：

| 层级 | 项目 |
|---|---|
| 文件 | 来源、版本、哈希、页数、兼容软件 |
| 页面 | 节数、纸张、方向、边距、页眉页脚、页码 |
| 表格 | 数量、顺序、所在节、表宽、缩进、固定/自动布局 |
| 网格 | 逻辑列数、每列宽度、总宽度 |
| 行/单元格 | 行数、行高、跨页、重复表头、gridSpan、vMerge、边框、内边距 |
| 对象 | 内容控件、表单域、图片、绘图、文本框、书签、关系 ID |
| 页面锚点 | 代理人、特殊编号项目、证据提示、调解区、落款 |

没有指纹和基线页面图，不进入多主体复制、合并修复或大范围填制。

## 7. G2 指令锁定

每项指令记录：

| 指令 ID | 对象 | 精确位置 | 新值/动作 | 来源 | 允许关联修改 | 禁止范围 | 状态 |
|---|---|---|---|---|---|---|---|

点改任务另建白名单：

| 白名单 ID | 基线值 | 目标值 | 文档位置 | 结构影响 | 批准状态 |
|---|---|---|---|---|---|

将“只改这里”“其余不变”视为强边界。只能检索关联位置并报告，不能未经批准同步改写。

## 8. G3 字段锁定

四张表分别维护：

### 主体字段

`主体 ID、角色、类型、姓名/名称、证件/统一代码、地址、负责人、联系方式、代理人、来源、状态`

### 事实字段

`事实 ID、时间、地点、行为主体、行为/事件、对象、结果、来源材料及页码、争议状态`

### 诉请/金额字段

`请求 ID、权利人、义务人、行为/给付、责任方式、金额/算法、截止日、法源、证据 ID、状态`

### 证据字段

`证据 ID、准确名称、形成日期/主体、页码范围、证明目的、对应事实/争点/诉请、归属主体、状态`

状态只使用 `L/D/P/X/NA/UK`。`P/X` 不得伪装成已确认文本。

## 9. 阻断与升级

出现以下任一项，不得标记 `RELEASE`：

- 当前母版或案由无法确认；
- 用户文件与现行官方版本冲突未处理；
- 法院、核心主体、责任主体、核心诉请或关键金额缺失/冲突；
- 多主体已经混写且无法可靠拆分；
- 金额链不能闭合；
- DOCX 包损坏或结构差异超出白名单；
- PDF 渲染存在裁切、错位、乱码、勾选失真或异常分页；
- 签名、日期、联系方式、调解或代理权限未经授权；
- 仅有 PDF 且未获重建授权。

可以继续形成明确标记限制的 `DRAFT` 或 `REVIEW` 报告，但不得把缺口隐藏在正式文书中。

## 10. 更新记录

每季度或出现新通知、母版替换、平台升级、法律修改、法院退回理由时，更新：

- 官方来源和访问日期；
- 受影响的母版路由；
- 历史规则废止/新增；
- 新的 P0/P1 缺陷码；
- 表格、勾选和渲染兼容性经验。

不得直接覆盖旧基线；提高版本号并保留适用日期。
