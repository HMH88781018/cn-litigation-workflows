## 1. 唯一真源与位置映射

同一字段不得在多份文书中分别手工维护。为每个关键字段建立唯一 ID 和真源值：

| 字段 ID | 锁定值 | 来源 | 起诉状位置 | 计算/证据位置 | 其他文书位置 | 同步规则 |
|---|---|---|---|---|---|---|
| PTY-* | 主体名称/身份 | 身份/登记材料 | 主体栏、诉请、事实 | 证据归属 | 保全/送达等 | 逐字一致 |
| AMT-* | 金额/参数 | 计算真源 | 完整诉请、要素栏 | 计算表、证据 | 保全/标的额 | 批准后全链同步 |
| DAT-* | 日期 | 原始材料 | 事实、请求 | 计算期间/证据 | 程序申请 | 时间线一致 |
| AUTH-* | 代理权限 | 本案授权书 | 代理人栏 | 程序材料 | 相关申请 | 不沿用旧案 |

字段变化时先检索所有位置，再决定哪些关联修改属于当前批准范围。

## 2. 诉请闭合

建立矩阵：

| 请求 ID | 权利人 | 义务人 | 完整请求 | 构成事实 ID | 法源 | 证据 ID | 金额公式 | 异常 |
|---|---|---|---|---|---|---|---|---|

正向检查：每项诉请均有明确主体、可执行内容、事实、法源和证据。反向检查：每项核心证据均有明确证明对象，不存在与案件无关或名称漂移的材料。

强制核对：

- 上方完整诉讼请求叙述区与下方要素栏双填；
- 两处主体、责任方式、金额、期间和截止日同义同额；
- 事实不能只写结论，要能支撑请求构成要件；
- 不主张的赔偿/费用项目不得在明细表中保留为已请求项目；
- 新增或删除一项诉请必须触发事实、金额、证据和其他程序文书的关联检查；
- 不以“详见附件”取代母版要求的核心诉请或事实。

## 3. 金额闭合

### 3.1 每项金额记录

`项目、权利人、基数/数量、期间、标准、公式、舍入、金额、截止日、证据 ID、是否计入总额`

### 3.2 计算原则

- 先在受控计算真源中复算，再把冻结值写入 Word；
- 金额通常保留两位小数，舍入规则明确；
- 利息/违约金写清本金基数、起止日、分段、标准、天数、暂计截止日和是否计至清偿；
- 多段期间不得重叠或漏段；
- 多权利人分别小计，再汇总案件总计；
- 不通过手改合计来掩盖分项冲突；
- 用户给定总额与复算差异时，先报告差异，取得决定后全链同步。

闭合公式：

```text
Σ(计入总额的分项金额) = 完整诉请总额
完整诉请总额 = 要素栏总额
要素栏总额 = 计算表总额
需要引用时：计算表总额 = 标的额/保全金额/其他程序文书引用额
差额 = 0.00 元
```

金额变更时重新检查所有文本、表格、计算参数和证据，不只改单个金额格。

## 4. 证据清单与证据材料

### 4.1 区分三类材料

- 证据清单：向法院说明证据名称、证明目的、页码和对应争点/诉请；
- 证据材料：按冻结顺序合并、连续编页的实体材料；
- 身份/程序材料：身份证明、主体资格、授权委托、律师执业材料等，按法院要求单列，不冒充案件实体证据。

授权委托书、律所函、律师证复印件、当事人对律师的陈述以及文书制作记录原则上不得列为证明实体争议事实的证据。身份证明材料用于主体资格，不当然列入实体证据清单。当前法院或本案指令有固定分类时从其要求，但不得改变其证明性质。

### 4.2 固定生产顺序

1. 完整读取原材料；
2. 去重、辨真和确定证据边界；
3. 冻结证据顺序；
4. 按顺序合并材料；
5. 在最终材料册中连续编页；
6. 冻结材料 PDF；
7. 从最终材料册回填证据清单页码；
8. 核对起诉状、计算表和证据清单引用；
9. 需要提交人/提交日期时按本案样本处理；未经指令默认留出实际填写空间。

不得先猜页码再合并材料，也不得在回填后继续插入材料而不更新清单。

### 4.3 证据清单列序

第一顺位是本案锁定的法院/用户样本。无固定样本时采用：

`争点/诉请 → 证明目的 → 证据名称 → 页码范围`

可另设序号列。不要把某一历史案件的列序描述成全国统一格式。

每项证据至少具有：准确名称、形成主体/日期（必要时）、页码范围、具体证明目的、对应诉请/争点和归属主体。空泛的“证明案件事实”不合格。

聊天记录、录音录像和图片不得选择性截取到扭曲事实；保持必要上下文、原始载体和形成主体，不能用制作者摘要替代原件。

## 5. 多主体归属

同案多名原告、伤者、权利人或被告时：

- 每名主体使用独立主体 ID；
- 每名主体的病历、票据、工资流水、损失期间和金额分别归属；
- 不跨人串用证据、基数或损失；
- 共同证据明确其覆盖主体和证明范围；
- 分别形成个人小计，再汇总案件总计；
- 分诉/合并起诉尚未决定时，把该问题标为 `BLOCK`，不得先混表。

数量闭合：

```text
材料中的当事人数
= 字段锁定表中的主体数
= 起诉状中的独立主体模块数
= 诉请责任主体数
= 事实/证据映射主体数
```

## 6. 内容复核

第二复核人直接对照原始材料，不能只看制作者摘要。至少检查两遍：

### 第一遍：逐字段

- 法院、程序、案由、管辖和期限；
- 姓名/名称、异体字、证件号码、地址性质、公司负责人；
- 代理权限、联系方式、签名/日期处理；
- 每项诉请、责任方式、金额、期间和截止日；
- 时间线、主体行为和原件对应；
- 证据名称、顺序号、材料页码、证明目的和归属。

### 第二遍：跨文书闭合

- 起诉状上下两处诉请；
- 起诉状与计算表；
- 起诉状与证据清单；
- 计算表与证据材料；
- 起诉状与保全、鉴定或其他程序申请；
- DOCX 与 PDF 的关键文字和勾选。

缺陷分级：

| 级别 | 例子 | 放行 |
|---|---|---|
| P0 | 错法院、错案、错主体、错证件号、错诉请、错金额、错母版、文件损坏 | 必须清零 |
| P1 | 地址、日期、核心事实、证据编号、代理权限、必要栏目、跨文书不一致 | 必须清零 |
| P2 | 不影响提交的轻微样式或内部记录问题 | 记录并决定 |

## 7. 视觉复核

必须执行：DOCX 保存重开 → 转 PDF → 全页 PNG → 100%逐页 → 关键区 200% → 黑白打印/预览。

逐页检查：

- 纸张、方向、页边距、页眉页脚和页码；
- 表格没有越版心、裁切、重叠、边框断裂、双线或列宽漂移；
- 长姓名、公司名、地址、证件号和金额完整；
- 没有字体替换、倒置、竖排、乱码或异常缩放；
- 合并单元格和多主体模块完整；
- 长表重复表头正确；
- 短原子模块不拆，长事实不存在因 cantSplit 造成的巨幅留白；
- 代理人、特殊编号项目、证据提示、调解区和落款正常；
- 勾选为空心框内 `√`，无黑块、蓝底、框外、重复或漂移；
- 没有本次编辑新增的意外空白页；母版固有页不得未经确认删除；
- 具状人、签章和日期有足够实际签署空间。

文字提取无法证明图片勾选、边框、合并或分页正确。视觉检查不可被文本比较替代。

## 8. 定点修改验收

建立修改日志：

| 修改 ID | 文件位置 | 修改前 | 修改后 | 来源 | 关联位置 | 是否批准 |
|---|---|---|---|---|---|---|

冻结基线哈希、页数、结构指纹和页面图。完成后比较：

- 文本差异；
- 结构差异；
- 勾选/对象差异；
- 页面图差异。

通过条件：

```text
实际差异集合 = 批准差异集合
未授权差异集合 = ∅
```

范围外已知错误只列入报告。只有当指定修改无法不影响结构或关联字段时，停止并请求扩大白名单或进入 `REPAIR`。

## 9. RELEASE 标准

| 指标 | 标准 |
|---|---:|
| 当前正确母版、法院、案由确认 | 100% |
| 未批准表数/列网格/合并/分节差异 | 0 |
| 表格越过可打印区域 | 0 |
| 多主体独立模块率 | 100% |
| 跨主体姓名/证号/日期/金额污染 | 0 |
| 诉请—事实—法源—证据覆盖率 | 100% |
| 金额复算差额 | 0.00 元 |
| 证据页码与最终材料册一致率 | 100% |
| 勾选语义与真值表一致率 | 100% |
| DOCX/PDF/打印勾选一致率 | 100% |
| 裁切、重叠、乱码、边框断裂 | 0 |
| 意外空白页、落款拆页 | 0 |
| DOCX 打开—保存—重开 | 通过 |
| 全部页面视觉检查率 | 100% |
| P0/P1 | 0 |

任一未通过即保持 `DRAFT`，不得通过文件名或回复暗示已经正式放行。

## 10. 交付清单

默认提供：

- 要素式起诉状 `.docx`；
- 同源渲染 `.pdf`；
- 任务范围内的金额/利息计算表；
- 证据清单及冻结的证据材料；
- 必要的保全、鉴定或其他程序申请；
- 交付说明：成果、版本、修改点、明确未修改范围、签名/日期待办、高风险、唯一有效版和已作废旧版。

文件名应包含案件简称、文书类型、版本和日期；避免 `最终版2`、`最新最终` 等无法追溯名称。旧版标为 `SUPERSEDED`，不得与当前有效版混放或混交。
