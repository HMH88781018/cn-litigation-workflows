## 1. 对象分类与施工权限

先识别对象，禁止把不同对象当成普通 Word 表格统一处理。

| 对象 | 典型内容 | 默认权限 |
|---|---|---|
| 官方要素表格 | 当事人、诉请、事实、程序选择、证据提示、落款 | 锁定；只原位填写、按说明扩容或复制完整模块 |
| 案件配套表格 | 金额/利息表、证据清单、证据材料目录 | 先锁用户/法院样本；无样本时按数据关系设计 |
| 说明性图表 | 时间线、主体关系、证据对应图 | 仅作辅助，不能替代事实、诉请和证据 |
| 内部控制表 | 字段锁定、差异白名单、放行卡 | 可重新设计，但不得混入提交正文 |

技术对象继续分类：

- 原生 `w:tbl`；
- 含 `gridSpan` 或 `vMerge` 的复杂表格；
- 嵌套表格；
- `w:sdt` 内容控件或 legacy 表单域；
- `w:drawing` 行内/浮动图片；
- 文本框、形状或静态图片表格；
- PDF/扫描件而无可编辑 DOCX。

官方表格必须满足三项不变量：

- 语义不变量：栏目、要素、顺序、勾选含义不变；
- 拓扑不变量：表数、网格、合并链、主体模块和分节边界不变，批准差异除外；
- 渲染不变量：DOCX、PDF和打印无裁切、错位、断裂、乱码、黑块或异常空白页。

## 2. 母版结构指纹

仅比较“页数、表数、行数”不够。至少记录：

| 层级 | OOXML/对象 | 锁定内容 |
|---|---|---|
| 页面 | `w:sectPr` | 纸张、方向、上下左右边距、装订线、页眉页脚距离、分栏、页码起始 |
| 表格 | `w:tblPr` | `tblW`、`tblInd`、`tblLayout`、对齐、边框、表格内边距、浮动属性 |
| 网格 | `w:tblGrid` | 逻辑列数、各 `gridCol` 宽度、总宽度 |
| 行 | `w:trPr` | 行高及规则、`cantSplit`、`tblHeader`、gridBefore/gridAfter |
| 单元格 | `w:tcPr` | `tcW`、`gridSpan`、`vMerge`、边框、内边距、垂直对齐、文字方向 |
| 段落 | `w:pPr` | 缩进、行距、段前后、制表位、keepNext/keepLines、分页 |
| 文字 | `w:rPr` | 中文/西文字体、字号、加粗、隐藏、上下标、方向 |
| 控件 | `w:sdt`/form field | 类型、状态、ID、绑定关系 |
| 绘图 | `w:drawing` | inline/anchor、尺寸、关系、docPr ID |
| 关系 | `.rels` | 页眉页脚、图片、超链接、外部对象目标 |
| 页面锚点 | 实际渲染 | 代理人、特殊编号项目、证据提示、调解区、具状人/签章/日期 |

指纹规范化时可以忽略正常变化的 `rsid`、临时编辑 ID 和 proofing 标记，但不得忽略修订、批注、内容控件、分页属性或关系断裂。

运行：

```bash
python scripts/docx_audit.py 母版.docx --json 母版指纹.json
python scripts/docx_audit.py 候选稿.docx --json 候选指纹.json
python scripts/docx_diff.py 母版.docx 候选稿.docx --json 结构差异.json
```

审计默认以哈希代替输入文件名和外部 relationship 目标，并枚举包内所有
`.rels`（包括 package、主文档、页眉页脚、脚注、批注和嵌入对象关系）。只有在受控环境中确需
定位原值时才使用 `--include-sensitive-metadata`；含原值报告不得进入公开
Issue、PR、CI 或对外共享材料。任何声明为 External，或指向 URI、UNC、`file:`
及绝对文件路径的 relationship 均产生 `P1`，须核验其
必要性、协议、域名、查询参数和跟踪风险；非必要链接在放行前移除。

DOCX 先经过压缩包和 XML 安全预检：压缩包大小、成员数、单成员/总解压大小、
压缩比和 XML 大小超过限制，或发现 `DOCTYPE`/`ENTITY`，一律 `P0` 失败关闭。
限额是本地资源保护边界，不代表文件内容可信；超限文件不得通过提高限额直接
放行，应先在隔离环境查明来源并取得安全复核。

脚本报告只作机械证据；必须结合批准白名单和逐页渲染判断。

## 3. 页面与表格几何

Word 常用单位：

- 1 英寸 = 1440 dxa；
- 1 厘米约 = 567 dxa；
- 1 英寸 = 914400 EMU。

对每个分节分别计算：

```text
正文可用宽度 B = pgW - marLeft - marRight - gutter
```

有效表格宽度：

1. `tblW` 为正 `dxa`：取该值；
2. `tblW` 为 `pct`：取 `B × value / 5000`；
3. `tblW` 为 `auto` 或 0：取 `sum(gridCol)`；
4. 同时比较 `tblW` 和 `tblGrid` 总和。

常见左对齐固定表格必须满足：

```text
tblInd >= 0
tblInd + effectiveWidth <= B
```

居中表格左边界为 `(B-W)/2`，右对齐为 `B-W`。遇到 `tblpPr` 浮动表格时不得套用普通公式，应标为高风险并实际渲染。

同时检查：

- 每行逻辑列覆盖等于 `tblGrid` 列数；
- 横向合并宽度等于所跨网格列宽之和；
- 嵌套表格使用父单元格可用宽度，而不是页面宽度；
- 页面分节归属正确，不能把文档最后一节参数套给全部表；
- 表格未进入页眉、页脚或不可打印区。

官方母版保持原 `fixed/auto` 设置。不得启用 AutoFit 来掩盖长名称或地址，也不得用 PDF 转换器自动缩放掩盖表宽溢出。

## 4. 操作风险分级

| 级别 | 操作 | 控制 |
|---|---|---|
| 安全 | 在已批准单元格原位填字、按原控件改变状态、允许最小行高自然增长 | 仍需字段来源和渲染检查 |
| 受控 | 复制完整主体模块、复制说明允许的整行、增加规范附页、调整完整模块前分页 | 必须进入差异白名单 |
| 高风险 | 增删列、改变网格/合并、列宽、分节、边距、页眉页脚、控件类型 | 原则不做；确需时书面授权并全量复核 |
| 禁止 | 空格/Tab模拟表格、截图代替可编辑表、浮动框覆盖、粘贴Excel对象、全局替换方框、全表自动重建 | 不执行 |

不得提供一键“自动修复 Word 格式”“自动删除空白页”“自动缩字体”“自动重新合并单元格”“自动把全部行设为 cantSplit”。

## 5. 文字填入与扩容

### 5.1 原位编辑

不得对官方母版整格使用 `cell.text = ...` 或整段使用 `paragraph.text = ...`。这会重建段落/run，并可能删除：

- 字体、字号和语言属性；
- 制表位、换行和段落属性；
- 方框图片或内容控件；
- 隐藏文字、字段和书签；
- 特殊边距和分页设置。

按 `表格 ID + 行组 + 逻辑列 + 栏目锚点 + 前后文` 联合定位。只替换目标 run 中的占位文字或在指定 run 位置插入，保留原 `pPr/rPr` 和非文字对象。

禁止未建立字段坐标时全局替换同名金额、日期或姓名。需要保留首尾空格时设置 `xml:space="preserve"`，但不得用连续空格模拟对齐。

检索并解释新增的异常属性：`textDirection`、`vert`、`rtl`、`bidi`、`fitText`、异常 `vertAlign`。不得通过 `fitText` 强压文字。

### 5.2 扩容顺序

1. 保持原字号、列宽、边距，让行高自然增长；
2. 在原单元格内按字段边界换行或增加规范段落；
3. 多主体时复制完整洁净模块；
4. 母版明确允许时复制完整要素行；
5. 仍不足时使用规范附页，并从原栏准确引向附页；
6. 局部字号调整只作为最后手段，需明确批准和渲染验证。

不得为减少页数压缩字距、行距、页边距或删除栏目。

## 6. 合并单元格与多主体复制

### 6.1 合并链

- 横向合并由 `gridSpan` 表示；
- 纵向合并必须保持 `restart → continue → ...` 完整链；
- `continue` 必须有前置 `restart`，起始逻辑列和跨度必须一致；
- 不得只复制合并区域的一行或一部分；
- 不得在已填内容后重新执行 Word 的“合并单元格”；
- 合并损坏时，从洁净母版恢复完整行组，不凭视觉拼接。

`python-docx` 的 `row.cells` 可能重复呈现或隐藏合并格，不能据此推断真实网格。涉及 `gridSpan/vMerge` 时读取底层 XML。

### 6.2 多主体模块

执行：

1. 标记自然人、法人/非法人组织、代理人模块的精确起止行；
2. 从未填写、未勾选的洁净种子模块深度复制完整 `<w:tr>` 行组；
3. 在同一表格和批准位置插入，不跨分节；
4. 保持行高、边框、合并、段落、控件和图片；
5. 检查并保证绘图 `docPr id`、书签、内容控件、批注范围及相关 ID 唯一；
6. 先复制空模块，再分别填入各主体；不得从已填写模块复制；
7. 检索姓名、出生日期、性别、证件号等跨主体污染和模板残留；
8. 核对 `材料主体人数 = 独立模块数 = 诉请责任主体数 = 事实/证据映射主体数`。

不得把“被告二、被告三”以换行方式塞入一个自然人信息格。左侧分类标签是否纵向合并只按母版，不因多人而重画。

## 7. 勾选框

### 7.1 建立真值表

| 勾选 ID | 栏目/选项 | 单选/多选 | 应选状态 | 来源 | DOCX | PDF/打印 |
|---|---|---|---|---|---|---|

勾选必须来自材料、当事人真实意思或明确指令。调解、保全、鉴定、送达、代理权限等不得由制作者默认。

### 7.2 技术分支

按原对象处理：

- 内容控件：只改变同一控件状态；
- legacy 表单域：只设置同一表单域；
- 普通 `□` 字符：保留原位置和字体，使视觉呈现为空心框内 `√`；
- Wingdings/Webdings：不得机械转为普通中文字体；
- 静态图片框：避免浮动形状覆盖；确需图片时使用经校准的行内黑白对象并验证关系；
- 浮动 `wp:anchor`：默认不用于勾选，易跨软件漂移。

唯一视觉标准：框线完整、背景无色、`√` 完全在框内；未选框保持空白。禁止实心黑块、蓝底、框外勾、`[]`、重复空框、选中项旁残留第二个框或基线漂移。

文本提取看不到图片状态，因此同时盘点绘图关系和逐页图；在 DOCX、PDF、黑白打印及常用移动端至少检查一次，关键框按 200% 查看。

## 8. 行高、对齐与分页

### 8.1 行高与内边距

- 可填写内容行保持原 `atLeast` 或自然高度；
- `exact` 只沿用母版已有的短标题行；
- 不得把内容行设为固定高度导致截断；
- 母版未显式设置 `tcMar` 可能表示继承样式，不能理解为 0；不得批量注入统一内边距；
- 新建附表可统一内边距，但要随页面和字号验证。

### 8.2 对齐

- 栏目名、序号、页码可居中；
- 事实、地址、证明目的、公式说明等长文本左对齐并顶端对齐；
- 金额通常右对齐；
- 不得把全表单元格统一垂直居中。

### 8.3 跨页决策

| 内容 | 处理 |
|---|---|
| 短标题、短勾选行、金额合计行 | 可 `cantSplit` |
| 单行代理人、短主体模块 | 原则保持完整；必要时模块前分页 |
| 多行法人模块 | 各行不拆，渲染决定是否整体前移 |
| 长事实、长证明目的 | 允许自然跨页或转附页 |
| 超过一页的单个行 | 不得 `cantSplit`；拆逻辑子项或附页 |
| 表格标题和首行 | 保持在一起 |
| 具状人、签章和日期 | 整块同页并留足签署空间 |

禁止全表统一 `cantSplit`。数据行中 `cantSplit` 比例异常高时列为分页风险。不要在表格单元格内随意插硬分页符；优先在完整模块前使用受控分页属性并渲染验证。

跨页证据清单、计算表和内部长表可用连续顶部行设置 `tblHeader`；不得擅自给官方起诉状全表加重复表头。第二页的列序和列宽必须与首表一致。

每次专项查看：代理人模块、模板中的高风险编号项目、证据提示、调解区、长事实方向、落款、页码和分节边界。

## 9. 长表、计算表和证据表

### 9.1 计算表

推荐字段：

`序号 | 项目 | 基数/数量 | 期间/标准 | 计算式 | 金额 | 是否计入总额 | 依据/证据`

规则：

- 计算真源放在受控计算表或程序，Word 只填冻结值和可阅读公式；
- 明确舍入、起止日和暂计截止日；
- 每一金额行映射证据 ID；
- 多权利人分别建表和小计，再汇总案件总计；
- PDF 中复核小数点、负号、百分号、乘号和日期连接号。

### 9.2 证据清单

先服从本案锁定样本。无固定样本时采用：

`序号（可选） | 争点/诉请 | 证明目的 | 证据名称 | 页码范围`

排版：

- 一项证据原则上一行；
- 多份材料属于同一证据时，在同格分段列明；
- 不用纵向合并把多项证据绑成一个争点；
- 名称和证明目的顶端左对齐；
- 页码居中，尽量不换行；
- 多页重复表头；
- 短证据行不拆，过长证明目的拆为可独立理解的子项；
- 多名伤者/权利人分别成组、归属和核算页码。

材料顺序：先定序 → 合并成册 → 连续编页 → 冻结 → 回填清单 → 核对起诉状和计算表引用。

## 10. 说明性图表

正式起诉状原则上不加入装饰性流程图、统计图或彩色信息图。确需时间线、主体关系或计算关系时，作为附页并确认受诉法院接受方式。

每个说明性图表登记：图表 ID、标题、数据来源、材料页码、口径、单位、截止日、推断标识、制作人和复核人。

要求：

- 不使用 3D、截断坐标轴、仅靠颜色区分或无证据推断；
- 黑白打印可辨；
- 图表不得替代诉请、事实和证据的文字表达；
- 使用行内对象，宽度不超过版心；
- 优先矢量，并在跨软件风险较高时保留清晰 PNG。

## 11. 仅有 PDF 或母版损坏

执行顺序：

1. 冻结问题文件，记录哈希、页数和症状；
2. 从最高人民法院、受诉法院、平台或用户留存版本重新取得官方 DOCX；
3. 能取得洁净母版时重新映射字段，不在损坏稿上继续打补丁；
4. 确无 DOCX 时取得《重建授权》，说明不能恢复 PDF 中不可见的隐藏结构；
5. 先测量纸张、边距、表数、网格、合并、边框、字体、方框和分页，形成重建蓝图；
6. 先建页面与表格拓扑，再录栏目文字，最后填案件数据；
7. 将来源 PDF 和重建 PDF 逐页并排或叠加比对；
8. 栏目名称、顺序、合并、边框和控件 100% 复核；
9. 提高主版本号，由第二人全量复核；
10. 无法可靠复刻时列明差异和风险，不声称“与原版完全一致”。

## 12. 结构与页面验收

执行三重差异：

1. 文本差异：字段值、关键文字、勾选语义；
2. 结构差异：表数、网格、行列、合并、边框、宽高、控件、分节和分页属性；
3. 页面图差异：实际渲染位置、裁切、留白、边框和勾选。

放行指标：

| 指标 | 标准 |
|---|---:|
| 未批准表/列/合并/分节差异 | 0 |
| 表格超出版心 | 0 |
| 跨主体字段污染 | 0 |
| 截断、压线、重叠、乱码 | 0 |
| 边框断裂或列宽漂移 | 0 |
| 勾选黑块、框外、重复、错位 | 0 |
| DOCX/PDF/打印勾选一致率 | 100% |
| 意外空白页和落款拆页 | 0 |
| 关键页面逐页检查率 | 100% |

修改任一字段后重新生成并检查全部页面，不只看修改页。

## 13. 故障—原因—修复矩阵

| 故障 | 常见原因 | 修复顺序 |
|---|---|---|
| 表格右侧裁切 | 页边距变大、缩进+表宽超版心 | 先恢复分节，再核对 tblW/tblGrid/tblInd |
| 列宽漂移 | AutoFit 或网格不一致 | 恢复母版布局和网格 |
| 合并断裂 | 漏复制 vMerge 行 | 从母版恢复完整行组 |
| 字体/方框消失 | 整格 `cell.text` 重建 | 恢复原格，按 run 局部替换 |
| 长地址推宽 | 自动列宽 | 固定原网格，让行高增长 |
| 文字被截 | exact 行高 | 恢复原值或 atLeast |
| 巨幅空白 | 长行或全表 cantSplit | 放开长行或转附页 |
| 主体串位 | 多人同格或从已填模块复制 | 复制洁净完整模块并逐字段排污 |
| 勾选黑块/蓝底 | 字体、填充或图片错误 | 恢复空心框内 √，逐格式验证 |
| 勾选漂移 | 浮动对象或图片过大 | 改回原控件/字符或校准行内对象 |
| Word 提示修复 | XML关系断裂或 ID 重复 | 从洁净母版恢复，检查关系与唯一 ID |
| 数字竖排/倒置 | 误入单位格或 textDirection/fitText 异常 | 恢复原段落/run属性并归位 |
| 证据表第二页无列名 | 未设置连续顶部表头 | 正确标记重复表头 |
| 页码全部失效 | 编页后又插材料 | 再冻结材料并重新回填 |
| 计算总额未更新 | 手改或依赖未刷新的域 | 回到计算真源全链复算 |
| 转 PDF 多空白页 | 分节、硬分页、末尾段落或 cantSplit | 对照母版逐层最小修复，不自动删除 |

通用修复顺序固定为：页面/分节 → 表格布局/网格 → 合并/单元格 → 行高/分页 → 段落/字体 → 文本/勾选 → 全量渲染。
